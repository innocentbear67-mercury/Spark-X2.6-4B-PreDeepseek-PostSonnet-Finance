# Finance prompt-set build contract — v1

Shared spec. Every subagent builds one area against this file. Do not edit this file or
`validate.py`; if you think a rule is wrong, work inside it and note the objection in NOTES.md.

Deliverable directory: `~/finance-prompt-set/data/<area_slug>/` containing exactly:

| file | contents |
|---|---|
| `generate.py` | deterministic generator, `random.Random(42)`, no network, no other deps |
| `prompts.jsonl` | exactly 1000 JSON objects, one per line, UTF-8, no BOM, trailing newline |
| `report.json` | machine summary (shape at bottom) |
| `NOTES.md` | <= 15 lines: authored seed families, known weaknesses, coverage gaps |

---

## 1. Provenance rules (hard)

1. **No network access.** Do not fetch filings, prices, transcripts, or datasets.
2. **Everything is synthetic.** No real company financials, no real filing text, no real
   transcript quotes. `source` is therefore only one of:
   - `synthetic:<area_slug>` — any row with a non-empty `context`, or any scenario row
   - `knowledge:finance_general` — context-free rows only, and only for **stable** facts
     (definitions, formulas, accounting identities, instrument mechanics, process rules).
3. **No time-sensitive facts in context-free rows.** Banned in those questions: *current,
   today, latest, right now, recently, this year, last year*. Rates, prices, index levels,
   tax thresholds and any "as of" number must be supplied inside `context`.
4. **Fictional entities only.** Keep a registry inside `generate.py`: 15–30 companies with
   name, sector, fiscal-year end, reporting currency. No real tickers, no real brand names.
   Names must read as plausible but obviously fictional (e.g. "Halcyon Grid Utilities",
   "Meridian Bancorp", "Kestrel Foods").
5. **`ground_truth` numbers are computed in code** from the same values written into
   `context` (or from the same fixture dict). Never hand-type a derived number. A row whose
   answer cannot be reproduced by re-running your own arithmetic is a defect.
6. **Self-contained.** Every fact needed to answer appears in `context` or `messages`.
   A reader with no outside knowledge must be able to produce `ground_truth`.

## 2. Row schema

Single-turn (10 keys exactly, no extras):

```json
{
  "id": "fin_<area_slug>_<abbr>_000001",
  "task": "calc",
  "source": "synthetic:<area_slug>",
  "context": "Units: $ in millions ...\n\n| Item | FY2025 | FY2024 |\n...",
  "question": "What was the FY2025 gross margin, in percent?",
  "ground_truth": 41.7,
  "answer_type": "number",
  "tolerance": "abs:0.1",
  "split": "train",
  "thinking": "on"
}
```

Multi-turn / tool-use (10 keys exactly; `messages` + `tools` **replace** `context` + `question`):

```json
{
  "id": "fin_<area_slug>_tool_000002",
  "task": "tool_use",
  "source": "synthetic:<area_slug>",
  "messages": [{"role": "user", "content": "..."},
               {"role": "assistant", "content": "..."},
               {"role": "tool", "content": "..."},
               {"role": "user", "content": "..."}],
  "tools": [{"name": "get_eps", "description": "...", "parameters": {"type": "object", "properties": {}, "required": []}}],
  "ground_truth": null,
  "answer_type": "text",
  "tolerance": "normalized",
  "split": "train",
  "thinking": "on"
}
```

Note: the brief's template wrote `"questions"`; the field guide says `question`. **Use
`question` (singular)** — the field guide and every normal checker assume it.

### Enums

- `task`: `calc` | `extraction` | `summarization` | `classification` | `qa` | `tool_use`
- `answer_type`: `number` | `text` | `label` | `list`
- `split`: `train` | `val` | `test`
- `thinking`: `on` | `off`
- `tolerance` by answer_type:
  - number → `abs:0.01` `abs:0.1` `abs:1` `abs:10` `rel:0.005` `rel:0.01` `rel:0.02`
  - text → `normalized` (case/punctuation/whitespace-insensitive) or `exact`
  - label → `exact`
  - list → `set` or `ordered`
  - `ground_truth: null` → `tolerance: null`
- `id`: `fin_<area_slug>_<abbr>_<6-digit seq>`; abbr = `calc` `extr` `summ` `cls` `qa` `tool`;
  seq unique within the file. Global uniqueness comes from the area slug.

### ground_truth typing

| answer_type | type | rule |
|---|---|---|
| number | JSON int/float, no units, no commas | expressed in the units declared in `context`; ratio questions must state the unit ("in percent") and the gt is the percent value (41.7, not 0.417) |
| text | string or null | null allowed for open-ended summarization/qa |
| label | string | must be non-null, <= 48 chars |
| list | array of strings | must be non-null, 1–40 items |

`messages` roles: `system` | `user` | `assistant` | `tool`; last message must be `user`;
`tool_use` rows need >= 1 tool and **>= 40% of them must have >= 3 messages** (a real
plan → call → result → answer sequence, not a single-shot ask).

## 3. Numbers and tables

- **One number format:** plain digits, no thousands separators (`4210`, not `4,210`),
  `.` as decimal point, `-` for negatives, no currency symbols inside numbers.
- Every `calc` row, and every row whose `ground_truth` is a number, must carry a units line
  as the first line of `context`, e.g.
  `Units: $ in millions except per-share amounts in dollars and percentages in percent.`
- Tables live inside `context` as markdown, header row + separator, fixed column meaning:

  ```
  | Item | FY2025 | FY2024 |
  |---|---|---|
  | Revenue | 4210 | 3850 |
  ```

- Period labels in tables must be explicit (`FY2025`, `Q3 FY2025`, `LTM to 30 Jun 2025`).
- Percentages: store the number as written under a `%` column header, or state "in percent"
  in the units line. Never mix the two conventions in one file.

## 4. Task quotas (per area, exactly 1000 rows)

| task | profile A (quant) | profile B (text) | profile C (agent) |
|---|---|---|---|
| calc | 280 | 120 | 150 |
| extraction | 220 | 220 | 150 |
| qa | 200 | 240 | 200 |
| classification | 100 | 220 | 50 |
| summarization | 100 | 100 | 50 |
| tool_use | 100 | 100 | 400 |
| **total** | **1000** | **1000** | **1000** |

`thinking`: **on** for `calc`, `qa`, `tool_use`; **off** for `extraction`, `classification`,
`summarization`. (Reasoning traces where reasoning pays; answer-only where it does not.)

## 5. Split policy

- 800 `train` / 100 `val` / 100 `test`, **stratified by task** so every split carries every
  task type (>= 3 rows per task per split).
- Assign splits by ranking a hash of `id` inside each task stratum — not by row order.
- No near-duplicate may straddle splits: a row whose question with digits masked matches a
  row in another split is a leak and fails the build.

## 6. Diversity floors (validator-enforced)

- >= 25 distinct question families per file (`question` with all numbers replaced by `#`).
- No single family above 4% of the file (<= 40 rows).
- >= 120 distinct contexts (context-bearing rows only).
- <= 8 rows per (context, question family) pair.
- Near-duplicate rate (`context + digits-masked question`, lowercased) must be 0.

## 7. Quality bar by task

- **calc** — one to three operations over the table; answer reproducible; distractors present
  (multiple periods, segments, per-share vs total); at least 30% multi-step (e.g. growth then
  margin, or EPS then P/E).
- **extraction** — verbatim span required; answer must be literally recoverable from
  `context`; include tables with merged/blank cells, footnotes, and unit traps.
- **summarization** — reference summary when `ground_truth` is present; must not introduce
  numbers absent from `context`.
- **classification** — fixed label set stated in the question (e.g. `{bullish, neutral,
  bearish}`); short rationale is not the label; labels balanced across the set (±10%).
- **qa** — either table-grounded multi-hop or stable-knowledge; no trivia that rots.
- **tool_use** — tools have realistic JSON-schema parameters; at least 40% multi-step;
  include wrong-argument recovery and "insufficient data → ask/abstain" cases.

## 8. Self-check before you report

```bash
cd ~/finance-prompt-set/data/<area_slug>
python3 ~/finance-prompt-set/validate.py prompts.jsonl --area <area_slug> --profile <A|B|C> --expect 1000
```

Fix every error and re-run until it prints `"status": "pass"` and exits 0. If the same error
survives two fixes, stop and report the exact message — do not loosen the data to dodge it.
